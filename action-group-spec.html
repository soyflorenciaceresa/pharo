Action Group

Spec del component set Action Group (página Action Group, nodo 669:189): molécula de 2 a 5 botones, con un único botón primario a la izquierda.

Component set 669:1894 variantesMolécula (compuesta por Button)Actualizado 29/09/2026

·Vista general

1Qué es

Action Group es un grupo horizontal de 2 a 5 botones en el que el primero es siempre la acción principal (Solid) y el resto son acciones secundarias (Outline).

2Cuándo usarlo

  • Para las acciones de la cabecera de un formulario de alta o edición: Guardar (primaria) + Cancelar (secundaria).
  • Para las acciones de la cabecera de un maestro: Nuevo (primaria) + Recargar y Exportar (secundarias).
  • Para acciones paralelas, que la persona elige de forma independiente (por ejemplo, Exportar o Imprimir).
  • Para acciones secuenciales, donde una lleva a la siguiente (por ejemplo, Guardar y continuar → Guardar → Cancelar).
  • Para el pie de un Modal con una acción de confirmación y una o más alternativas.

3Cuándo no usarlo

  • No usar cuando hay una sola acción → usar Button suelto.
  • No usar con más de 5 acciones → agrupar las secundarias en un menú de acciones [Supuesto — validar: aún no existe].
  • No usar para cambiar entre secciones de una misma pantalla → usar Tabs.
  • No usar para pasar de página en un listado → usar Pagination.
  • No usar para acciones por fila de una tabla → usar la columna de acciones del DataGrid.
  • No usar con dos o más botones primarios → dejar uno solo y pasar el resto a secundario.

4Variantes

Una propiedad de variante (Buttons) que define la cantidad de botones. En todas, el primero es Solid y los demás Outline. No hay variantes de tamaño.

Tamaño: el ancho depende del contenido (hug); el alto lo define el Button (33 px Solid, 35 px Outline).

5Estados

El grupo no tiene estados propios: cada botón hereda los estados del Button (Default, Hover, Pressed, Focus, Disabled).

  2. Botón primario — obligatorio, siempre uno y siempre el primero (izquierda). Capa: Primary. Instancia de Button con Variant=Solid.

7Propiedades (Figma)

PropiedadTipo (Variant / Boolean / Instance swap / Text)ValoresDefaultNotas
ButtonsVariant2, 3, 4, 52Cantidad de botones. Define cuántas capas Secondary hay.

El grupo no expone propiedades de texto ni de ícono. Para cambiar el texto de un botón, seleccionar la instancia de Button dentro del grupo y editar su propiedad Label.

Combinaciones inválidas o sin efecto

  • Más de un botón Solid dentro del grupo: inválido (regla básica: un solo primario).
  • Botón Solid que no está en primer lugar: inválido; el primario va siempre a la izquierda.
  • Menos de 2 o más de 5 botones: no existe variante; usar Button suelto (1) o un menú de acciones (más de 5).
  • Botones Text o Icon Only dentro del grupo: no contemplados hoy [Supuesto — validar].

[Supuesto — validar] Nombre y valores de Buttons (2–5) elegidos al crear el componente.

8Reglas de uso

✅ Hacer

  • Poner siempre un solo botón primario, en la izquierda del grupo.
  • Agrupar de 2 a 5 botones, ni más ni menos.
  • Ordenar los secundarios de mayor a menor importancia, de izquierda a derecha.
  • Agrupar solo acciones relacionadas: paralelas (Exportar / Imprimir) o secuenciales (Guardar → Guardar y continuar).
  • Escribir cada label con verbo en infinitivo, de 1 a 3 palabras y con mayúscula solo en la primera letra.
  • Usar instancias de Button y mantener el gap de spacing/sm (8 px).
  • Usar un solo Action Group por sección o por vista.

❌ No hacer

  • Poner dos o más botones Solid en el mismo grupo.
  • Poner el botón primario en el medio o a la derecha.
  • Superar los 5 botones: agrupar el resto en un menú.
  • Repetir la misma acción en dos botones del grupo.
  • Mezclar en un mismo grupo acciones que no tienen relación entre sí.
  • Desacoplar las instancias de Button para cambiar color o padding.
  • Dejar un botón Disabled sin explicar qué falta para habilitarlo.

9Notas de accesibilidad

Patrón WAI-ARIA APG: no hay un patrón dedicado. Cada botón sigue el patrón Button. El patrón Toolbar no aplica: no hay navegación con flechas entre los botones.

Teclado

TeclaAcción
TabMueve el foco al siguiente botón, de izquierda a derecha. El primero en recibir foco es el primario.
Shift + TabMueve el foco al botón anterior.
Enter / EspacioActiva el botón con foco.

Orden de foco: igual al orden visual (primario, secundario 1, 2…). Un botón Disabled se omite. El grupo no mueve el foco por sí mismo.

Lector de pantalla

  • Cada botón es un <button> nativo con su texto como nombre accesible: “Guardar, botón”. Un botón deshabilitado se lee “Guardar, botón, no disponible”.
  • Recomendado: envolver el grupo en un contenedor con role="group" y aria-label (por ejemplo “Acciones del formulario”). [Supuesto — validar]
  • No hay estados anunciados a nivel grupo.

  • Área táctil: cada botón mide 33 o 35 px de alto, por encima del mínimo AA de 24 × 24 px; el recomendado táctil es 44 px. La separación de 8 px evita toques cruzados.
  • No depender solo del color: el primario se distingue por su fondo sólido y por estar primero; el secundario, por su borde.
  • Movimiento: sin animación propia; los botones respetan prefers-reduced-motion (definido en Button).

10Componentes átomo relacionados

Usa internamente

  • Button (component set 591:1937): Variant=Solid para el primario y Variant=Outline para los secundarios, ambos en State=Default. Se personaliza solo la propiedad Label.

Hermanos / alternativos

  • Button: para una acción única.
  • Tabs: para cambiar entre secciones de contenido, no para ejecutar acciones.
  • Pagination: para moverse entre páginas de un listado.
  • Modal: contenedor donde suele ir un Action Group en el pie.

Dónde se usa hoy en el proyecto: el componente ActionGroup ya existe en el código y lo usan LayoutMaestroDataGrid (Nuevo / Recargar / Exportar), LayoutMaestroBasico (Guardar / Cancelar) y el footer del Modal de PerfilFormulario (Agregar / Cancelar).

·Pendientes

  • Definir la alineación del grupo (izquierda o derecha del contenedor) y qué pasa cuando no entra en una línea (responsive).
  • Decidir qué se hace con más de 5 acciones: ¿menú de acciones? Hoy no existe.
  • Los templates del código usan íconos en los botones (Nuevo, Recargar, Exportar, Guardar); el grupo de Figma no los incluye. Definir si se permiten.
  • Decidir si el grupo admite botones Text o Icon Only y si hace falta una variante destructiva.
  • Exponer el texto de cada botón como propiedad del componente en Figma (hoy se cambia entrando a la instancia).
  • Confirmar los nombres Buttons y los valores 2–5, y el uso de role="group" con etiqueta.
