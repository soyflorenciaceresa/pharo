Text field

Pharo Design System · Spec de componente · Fuente: Figma 327:22 (frame “Text field”, 4 variantes de State)

·Vista general (interactiva)

Texto de ayuda

Render fiel a los tokens leídos de Figma. State=Default, Focus, Disabled, Error (izq. → der.).

1Qué es

El Text field es un campo de una línea donde la persona escribe o edita un texto corto, acompañado de una etiqueta y, en error, de un mensaje de ayuda.

2Cuándo usarlo

  • Para capturar datos cortos en un formulario: nombre, apellido, correo, teléfono, ciudad.
  • Para ingresar un valor libre que no está en una lista predefinida (p. ej. nombre de un proyecto).
  • Para editar un dato existente en una pantalla de ajustes o perfil.
  • Para mostrar un error de validación asociado a un dato puntual, con un mensaje que explique cómo corregirlo.

3Cuándo no usarlo

  • No usar para textos largos o de varias líneas (comentarios, descripciones) → usar Text area en su lugar.
  • No usar para elegir entre opciones conocidas (país, categoría) → usar Select o Radio group.
  • No usar para activar o desactivar algo → usar Switch o Checkbox.
  • No usar para buscar en la app → usar Search field.
  • No usar para mostrar datos que la persona no puede editar → usar texto simple (o un campo de solo lectura, cuando exista).
  • No usar para fechas u horas → usar Date picker / Time picker.

[Supuesto — validar] Los componentes alternativos nombrados (Text area, Select, Search field, Date picker…) deben existir o estar planeados en Pharo.

4Variantes

En Figma existe una sola propiedad de variante (State). No hay variantes de jerarquía ni de tamaño: el ancho por defecto es 280 px y el alto es 54 px (72 px en Error, por el helper text).

VariantePara qué sirveEjemplo de uso
State=DefaultCampo vacío o en reposo; muestra el placeholder.Formulario de registro recién abierto.
State=FocusCampo activo; la persona está escribiendo.Al hacer clic o tabular al campo “Correo”.
State=DisabledCampo no disponible para editar.“Correo” bloqueado mientras se procesa el envío.
State=ErrorEl valor no pasó la validación; muestra helper text en rojo.“Ingresá un correo válido, por ejemplo nombre@dominio.com”.

Como hay una sola propiedad de variante, la matriz Variante × Estado es 1:1 (cada estado es una variante). Huecos detectados:

  • Hover no existe.
  • Filled en reposo, Focus + Error (campo con error que recibe foco) y Error + Disabled no existen.
  • El helper text solo aparece en Error; no hay helper text informativo en los demás estados.

8Reglas de uso

✅ Hacer

  • Usar siempre un label visible, en sentence case y de máximo 3 palabras (“Correo electrónico”).
  • Escribir el mensaje de error con causa y solución (“Ingresá un correo válido, por ejemplo nombre@dominio.com”), máximo ~80 caracteres.
  • Alinear campos en una sola columna, con separación consistente entre campos.
  • Usar los tokens (--border-input-*, --spacing-padding-input-*) y no valores fijos.
  • Validar al salir del campo (blur) o al enviar, no en cada tecla.
  • Mantener el ancho acorde al dato esperado (mínimo 280 px por defecto).

❌ No hacer

  • No usar el placeholder como reemplazo del label.
  • No mostrar “Campo inválido” u otros mensajes genéricos.
  • No indicar el error solo con el borde rojo.
  • No usar Disabled para ocultar por qué no se puede editar; explicar la razón cerca del campo.
  • No poner instrucciones críticas solo en el placeholder (desaparece al escribir).
  • No tapar el texto del label con mayúsculas sostenidas.

9Notas de accesibilidad

Teclado

TeclaAcción
TabMueve el foco al campo (queda en Focus). Disabled se omite.
Shift+TabMueve el foco al elemento anterior.
CaracteresEscriben en el campo.
← → Home EndMueven el cursor dentro del texto.
EnterEnvía el formulario si hay un botón de envío asociado.

El componente no mueve el foco por sí mismo. Al aparecer un error tras enviar, mover el foco al primer campo con error.

Lector de pantalla

  • Elemento nativo <input type="text"> con <label for> asociado (nombre accesible = Label).
  • Error: aria-invalid="true" y helper text enlazado con aria-describedby. Se lee: “Correo, cuadro de edición, no válido, Ingresá un correo válido…”.
  • Disabled: atributo disabled. Se lee: “Correo, cuadro de edición, no disponible”.
  • Para anunciar el error al aparecer, usar role="alert" o una región aria-live="polite" en el helper text.

  • Alto actual ≈ 38 px de campo + label: supera el mínimo AA de 24×24 px; se recomienda ampliar a 44 px de alto para toque.

Patrón APG: no hay un patrón dedicado; se aplica el de campo de texto nativo. Los ratios son estimados; validar con una herramienta de contraste.

10Componentes átomo relacionados

Usa internamente: texto Label/Small y Body/Base (estilos de texto). No anida otros componentes hoy. Sin íconos anidados.

Hermanos / alternativos:

  • Text area: para varias líneas.
  • Select: para elegir entre opciones conocidas.
  • Search field: para búsqueda con ícono y botón de limpiar.
  • Password / Number input: cuando el dato requiere enmascarado o formato numérico.

[Supuesto — validar] Estos componentes hermanos aún no fueron verificados en el file de Figma.
