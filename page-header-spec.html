Page header

Spec del component set Page header (página Page header, nodo 680:39): organismo de 3 variantes de Type (Home, Maestro y Form), compuesto por Breadcrumb, Toggle Icon y Action Group.

Component set 680:393 variantesOrganismoAncho: 1000 pxActualizado 29/09/2026

·Vista general

1Qué es

Page header es el encabezado de una pantalla: muestra su título y, según el tipo, un subtítulo, la ruta de navegación, el marcador de favorito y las acciones principales.

2Cuándo usarlo

  • Para abrir cada sección de la Home de Main y de un módulo, con título y subtítulo (Type=Home): por ejemplo Acceso rápido — “Tus maestros y procesos favoritos”.
  • Para la pantalla principal de un maestro o proceso (por ejemplo Buque), con el título, el favorito y los botones Nuevo / Recargar / Exportar (Type=Maestro).
  • Para las pantallas de formulario (alta, edición y vista), con la ruta de navegación, el título y los botones Guardar / Cancelar (Type=Form).

3Cuándo no usarlo

  • No usar para el título de un bloque dentro de un formulario (“Datos del buque”) → usar el encabezado de FormContainer o de Accordion.
  • No usar para el título de un diálogo → usar el encabezado del Modal.
  • No usar para cambiar entre secciones de una misma pantalla → usar Tabs.
  • No usar para la barra superior global (buscador, idioma) → usar TopBar.
  • No usar para mostrar solo acciones, sin título → usar Action Group o Button.

6Anatomía

  1. Contenedor — obligatorio. Capa: el propio componente (Type=…). Auto layout: en Home vertical (gap spacing/xs 4 px); en Maestro y Form horizontal con los botones a la derecha y alineados a la base (gap spacing/md 16 px). Ancho 1000 px, alto según contenido.
  2. Breadcrumb — opcional (solo Form). Capa: Breadcrumb. Instancias de Breadcrumb (State=Default con separador y State=Active para el ítem actual), separadas 8 px (spacing/sm).
  3. Título — obligatorio. Capa: Title. Estilo Heading/H1 (Inter Bold 24), color color/text/default.
  4. Subtítulo — opcional (solo Home). Capa: Subtitle. Estilo Body/Base (Inter Regular 14), color color/text/secondary.
  5. Favorito — opcional (solo Maestro). Capa: Toggle Icon. Instancia de Toggle Icon, a la derecha del título con 4 px de separación.
  6. Acciones — opcional (Maestro y Form). Capa: Action Group. Instancia de Action Group (Buttons=3 en Maestro, Buttons=2 en Form).

Composición ilustrativa. Los números del gráfico corresponden a la lista (el 4 aparece solo en Home).

7Propiedades (Figma)

PropiedadTipo (Variant / Boolean / Instance swap / Text)ValoresDefaultNotas
TypeVariantHome, Maestro, FormHomeDefine qué partes tiene el encabezado.

El organismo no expone propiedades de texto, boolean ni instance swap. Para cambiar el título o el subtítulo, se edita el texto dentro de la instancia. Los textos de la ruta de navegación y de los botones se cambian en la propiedad Label del Breadcrumb y del Button anidado.

Combinaciones inválidas o sin efecto

  • Home con botones o con favorito: no contemplado (las secciones de Home no llevan acciones).
  • Form con Toggle Icon: inválido; el favorito solo va en la pantalla principal de un maestro o proceso, nunca en sus formularios.
  • Maestro o Form con más de un Action Group: inválido (un solo grupo por encabezado).
  • Título vacío: inválido; el título es obligatorio en las tres variantes.

[Supuesto — validar] Nombre y valores de Type (Home / Maestro / Form) elegidos al crear el componente.

8Reglas de uso

✅ Hacer

  • Usar un solo encabezado de pantalla (Maestro o Form) por vista; en Home, uno por sección.
  • Escribir el título en una sola línea y con mayúscula solo en la primera letra: “Crear Buque”.
  • En Form, dejar como último ítem de la ruta (Active) el mismo nombre del título.
  • Poner las acciones a la derecha, con el botón primario a la izquierda del grupo (regla del Action Group).
  • Mostrar el favorito solo en la pantalla principal de un maestro o proceso de un módulo de negocio.
  • Usar instancias de Breadcrumb, Toggle Icon y Action Group; cambiar solo sus textos y valores.
  • Usar los estilos Heading/H1 y Body/Base y las variables de color y spacing.

❌ No hacer

  • Mostrar el favorito en formularios ni en las pantallas de Main (Usuarios, Perfiles, Empresas).
  • Poner ruta de navegación en las secciones de Home.
  • Poner más de un botón primario o más de 5 botones en el grupo de acciones.
  • Repetir el título del encabezado como título del bloque de contenido que sigue.
  • Desacoplar las instancias para cambiar tamaños, colores o separaciones.
  • Dibujar el encabezado con textos y botones sueltos en lugar de usar el componente.

9Notas de accesibilidad

Patrón WAI-ARIA APG: Breadcrumb (para la ruta de navegación). El organismo en sí no tiene un patrón dedicado.

Teclado

TeclaAcción
TabRecorre, en orden visual: ítems de la ruta (si son enlaces) → favorito → botones de acción. El título no es focusable.
Shift + TabMueve el foco al elemento anterior.
Enter / EspacioActiva el botón o el favorito; Enter también sigue un enlace de la ruta.

Orden de foco: igual al orden visual, de arriba abajo y de izquierda a derecha. El organismo no mueve el foco por sí mismo.

Lector de pantalla

  • El título es un encabezado: <h1> en Maestro y Form (uno por pantalla) y <h2> en las secciones de Home. Se lee: “Buque, encabezado, nivel 1”.
  • La ruta de navegación debería ser un <nav aria-label="Ruta de navegación"> con una lista; el ítem actual lleva aria-current="page". Se lee: “Ruta de navegación, navegación; Buque, enlace; Crear Buque, página actual”.
  • El favorito y los botones siguen lo definido en Toggle Icon y Action Group (aria-pressed, role="group" con aria-label).

Hermanos / alternativos

  • FormContainer y Accordion: encabezado de un bloque de contenido, más pequeño (16 px).
  • Modal: encabezado de un diálogo, con botón de cierre.
  • TopBar: barra global de la app (buscador e idioma), no el título de la pantalla.
  • Tabs: navegación entre secciones de una misma pantalla.

Dónde se usa hoy en el proyecto: el componente PageHeader ya existe en el código (prop type: home, maestro, form) y lo usan LayoutMaestroDataGrid, LayoutMaestroBasico, LayoutHomeModule y Main/Home. Main/Modulos y LayoutChat siguen con encabezado propio.

·Pendientes

  • Los templates usan íconos en los botones (Nuevo, Recargar, Exportar, Guardar, Cancelar); el Action Group de Figma no los incluye, así que las variantes salen sin íconos.
  • En el código la ruta de navegación ya tiene semántica (nav, aria-current) pero no hay un componente Breadcrumb aparte ni ninguna pantalla pasa enlaces todavía. Alinear código y Figma.
  • El color secundario (#6A7883) sobre el fondo de pantalla da 4,3:1 y no cumple AA para texto normal; definir un tono más oscuro o usar fondo blanco.
  • Definir el ancho real del encabezado: en Figma es 1000 px; en la app es el ancho de la pantalla (fill).
  • Definir si el encabezado de Maestro admite ruta de navegación (el template la soporta como opcional) y si Home puede llevar acciones.
  • Definir el comportamiento en pantallas angostas: título largo, botones que no entran (ver Action Group).
  • Confirmar el nombre Type y los valores Home / Maestro / Form, y si conviene exponer los textos como propiedades del componente.
